# Administration and recovery

Install the modular SVEXTRACT core on client and server, plus external compatible integrations. The retired all-mods bundle must not be installed alongside it. Loader minimum is >=0.18.4; pinned external Kotlin requires 0.19.5. See README.md and docs/INTEGRATIONS.md for the exact dependency revisions.

`/svextract lobby` or the protected Mission Control NPC opens the native mode screen. J opens the same lobby. Player commands also include `haven`, `skyrim`, `deploy` (Training only), `abort`, `progress`, `balances`, `companiongun`, and `loot`. Squad commands are `squad`, `squad invite <player>`, `squad accept`, and `squad leave`. Membership persists; shared squad deployment and public queues remain unavailable. Private Versus starts immediately with explicit bot actors; it does not claim to implement the requested two-minute public matchmaking queue.

Operations requires gear-risk confirmation in the lobby. Its current private extraction profile has optional research, physical supply caches and two Blackglass evacuation points. Surviving equipment and current item components settle on extraction. Death, abandonment and timeout settle an empty inventory. Training returns the original loadout; Versus restores the reserved personal inventory after removing temporary match equipment. Versus has no extraction loot. BEconomy balance reads work; authoritative currency payouts and shop purchases are unfinished.

`config/svextract/server.json`, `modes.json` and `loot.json` are validated at startup. Unsupported match engines cannot be enabled through configuration. Mode definitions remain immutable for the current runtime. `maps` are documented in MAPS.md; the pinned Vault terrain ships as server-side map data, without the Vault Hunters mod. Chunk preparation, main-thread block writes and active concurrency are bounded; instance capacity is global across both map pools.

Permission level 2 commands are `/svextract diagnostics`, `/svextract export`, and `/svextract reload`. JSON exports go to `<save>/svextract/reports/`. Performance settings and region spacing require restart; active sessions retain their configuration snapshot. Invalid reload retains the previous config. Invalid initialization disables deployment and can reject login when safe recovery is unavailable; inspect the actionable server error rather than deleting persistence data.

The journal is `<save>/svextract/journal.sqlite`, using one bounded writer, WAL and FULL synchronization. Back up the complete stopped save, including SVFrame, Cobblemon, BEconomy, vanilla playerdata and this journal. A live SQLite backup must include the WAL through the proper online-backup API.

Inventory snapshots are registry-aware NBT with item components. Reserve, activate, checkpoint and settle use transaction IDs and compare-and-set checks. One nonclosed raid per player is allowed. Settlement replaces the protected inventory, saves playerdata, verifies inventory by unique slot plus exact components/counts, dimension and game mode, forces the save durable, then closes the journal. Extraction progress increments once. Failed critical writes retain an interaction lock; do not clear a journal row just to unfreeze the player. Audit rows record transitions. Administrative arbitrary ownership overrides and repair GUI remain unfinished.

Live Operations/Versus disconnects retain the private session for the configured reconnect window. Actors pause while its human is disconnected. Expiry settles the mode's loss/restoration rules. Risk sessions checkpoint current gear/components on the bounded worker and flush at graceful shutdown. An interrupted ACTIVE Operations raid recovers checkpoint gear without unextracted raid-marked loot; RESERVED transactions recover their original snapshot. This deliberately favours preserving checkpoint gear on a server failure. Insurance, secure pouches and competitive player-to-player ownership transfers are unfinished.

The telemetry ring measures whole-server tick time/cadence. `pathRequests` counts this director's explicit requests, not every mod's navigation. `aiNanos` covers its decisions, not every entity tick. Payload bytes are estimates, and loaded chunk counts refer to the owned dimensions. Lifetime counters differ from rolling percentiles. Native software-rendered QA shares CPU with the server and is not a multiplayer capacity benchmark. Required gates, profiling and production acceptance remain open.

## Native storage and private defusal

Use the lobby's STASH / LOADOUT button, `/svextract stash`, or the physical Haven-9 stash terminal at (5,65,-8). Click an inventory stack to deposit, or a stored stack to withdraw. Transfers use empty slots and preserve whole stacks/components. The storage config supports 27–108 slots in pages of 27 and bounded request/concurrent-transfer limits. Do not shrink capacity below occupied slots; restore the previous capacity if validation rejects it. Config changes take effect after restart.

Storage transfers are recorded in `stash_transfers`, ownership in `stashes`, and PREPARED/CLOSED events in `audit` in the existing journal database. The player inventory stays protected between durable intent and verified/fsynced player save. A failed save retains the pending transfer for reconnect/restart recovery. Do not manually delete pending rows or copy old player data over committed storage. Back up the complete stopped test/save directory when investigating.

Protocol 4 requires the same current core on client and server. Point Blank and the RPG integrations remain external. Private Versus is now defusal; see `MODE_RULES.md`, `defusal.json` and `defusal-shop.json`. Public queue/autofill and BEconomy match payouts are still unfinished.

Instance preparation failures quarantine the affected slot. Admission has a configurable timeout (`performance.instancePreparationTimeoutTicks`, default 2400) and returns reserved equipment. A failed preparation is not automatically reused; resolve the error and restart the isolated instance pool. Pending equipment remains journaled if durable delivery itself fails.
