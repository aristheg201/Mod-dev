Physical cards are an additional acquisition path. Inventory items do not enter decks, database trading, or the collection until redeemed. Pack, starter, NPC, market, and duel semantics are preserved.

- Items: `svarcade_tcg:blank_card` (64) and `svarcade_tcg:physical_card` (1).
- Admin commands: `/cardworlds grantblank <player> [amount]` and `/cardworlds grantphysical <player> <cardId> [finish]`, permission level 3. Grants create items, without minting collection copies.
- Redemption uses the actual server-held stack. SQLite commits the physical token and serial in the same existing CardStore transaction. A surviving stale item can recover and consume its token without minting again. A different collector cannot redeem that token. Finder provenance survives redemption and subsequent trading.
- Capture uses Cobblemon 1.8.1's real basic-ball calculation, hit veto hooks, animation, and lifecycle. The scoped redirect intercepts the exact success storage insertion call before it reaches either party or overflow PC. Ordinary Poké Balls keep their normal insertion. A provider veto cannot refund a real Poké Ball. The capture projectile is non-persistent. Active captures block Card Worlds catalog reload.
- Card identity comes from the final hydrated catalog, canonical species, and satisfied registered aspects. The registered registry base is canonical for base species; theme prints without form identity are not competing wild bases. An explicit SpecialAspectCards identity supersedes its generated registry alias. The most specific remaining registered identity wins; equal specificity ambiguity is rejected with candidate IDs in the server log. No fakemon pack is required. Capture metadata records relevant identity aspects, species, original level, shiny state, finder, and time; IVs, EVs, moves, nature, and friendship are not Card Worlds statistics.
- Loot configuration: `config/svarcade-tcg/physical-loot.json`. Chances are per chest table; rarity weights choose a rarity first and then uniformly choose a card of that rarity from the current catalog. Restart the server after changing chest chances/table mappings. Each generated copy gets a new server UUID. Datapacks may use the `svarcade_tcg:random_physical_card` loot function.
- Visuals use one thin model, the existing CardRenderer/PokemonModels pipeline, and a bounded cache of 64 card fronts. Resource reload, language changes, catalog changes, and disconnect invalidate cached presentation. Resource packs can replace the item model/textures or provide `assets/svarcade_tcg/textures/physical_cards/<cardId>.png`; namespaced IDs use a slash in place of the colon. English and Vietnamese item/tooltips are included.

Build restoration: after the existing bootstrap and production/YGO overrides, run `python3 source-overrides/physical-card-worlds/apply.py`. It adds only the physical-card hooks and localization. New physical source and QA files are tracked directly. This is also wired into the existing branch CI.

Verification: `gradle test remapJar remapPhysicalQaJar`, then `gradle runPhysicalCardWorldsClient` and `python3 source-overrides/physical-card-worlds/verify_runtime.py`. The separate QA mod uses real integrated-server entities, actual interaction packets, the production remapped mod, and installed providers. It checks failure/success consumption, provider cancellation, rejected ownership and malformed items, capture identity/provenance, exact UUID absence from world/party/PC, duplicate callbacks, Survival/Creative full-inventory dropping and partial-stack overflow, chest-generated tokens, normal and recovered redemption, other-owner token rejection, collection sync, and the floating-card pop. Production JARs do not contain the QA driver.
